# Как завершить работу и сдать отчёты

Всё, что можно было сделать без доступа к GitHub, уже сделано: проект, `Dockerfile`,
пайплайн, README и два PDF-отчёта. Ниже — что осталось сделать вручную.

## 1. Подставить свой репозиторий в отчёты

В отчётах сейчас стоит заглушка `https://github.com/OWNER/task-tracker`.
Перегенерируйте PDF, указав реальную ссылку (и, при желании, ФИО и группу):

```powershell
$env:REPO_URL="https://github.com/ваш-логин/ваш-репозиторий"
$env:REPORT_AUTHOR="Иванов Иван Иванович"
$env:REPORT_GROUP="Группа 123"
python docs/report/build_reports.py
```

Файлы `docs/report/report-hw1-ci-cd.pdf` и `docs/report/report-hw2-docker.pdf`
перезапишутся. Заголовок титульного листа и дату тоже можно поменять
(`REPORT_DATE`) в начале `build_reports.py`.

## 2. Опубликовать репозиторий

```powershell
cd "D:\Документы\Проект по умолчанию"
git remote add origin https://github.com/ВАШ-ЛОГИН/ВАШ-РЕПОЗИТОРИЙ.git
git push -u origin main
```

Если репозиторий на GitHub был создан с README/лицензией, сначала подтяните его историю:

```powershell
git pull --rebase origin main
git push -u origin main
```

Важно: workflow реагирует на ветку `main`. Если ваша основная ветка называется иначе,
поправьте `branches:` в `.github/workflows/ci-cd.yml` (или переименуйте ветку).

## 3. Проверить прогон

1. Вкладка **Actions** → запуск `CI/CD` → оба job'а должны быть зелёными.
2. Первый прогон скачивает зависимости (дольше), повторный — берёт кэш.
3. Внизу страницы запуска — раздел **Artifacts** с jar-файлом.
4. Вкладка **Packages** репозитория → образ `task-tracker` с тегами
   `latest`, `main`, `sha-…`.
5. Сделайте пакет публичным: **Package settings → Change visibility → Public**.
6. Скачайте и запустите образ локально:

```powershell
docker pull ghcr.io/ваш-логин/ваш-репозиторий:latest
docker run --rm -p 8080:8080 ghcr.io/ваш-логин/ваш-репозиторий:latest
```

Примечание: в GHCR имя пакета — это имя вашего **репозитория**, приведённое к нижнему
регистру, а не `task-tracker`. Команда `docker pull` показывается прямо на странице
пакета — проще всего скопировать её оттуда.

## 4. Вставить скриншоты в PDF

Места под скриншоты обозначены пунктирными рамками с подписью «СКРИНШОТ: …».
Самый простой способ — открыть PDF в Word (или в редакторе PDF), либо вставить картинки
поверх рамок в любом редакторе (Acrobat, PDF-XChange, LibreOffice Draw).

### ДЗ 1 (`report-hw1-ci-cd.pdf`), раздел 8

| № | Что снять |
|---|---|
| 1 | Список запусков workflow во вкладке Actions (успешные push и PR) |
| 2 | Логи job `build-and-test`: `Cache restored from key: …` и `Tests run: 13` |
| 3 | Раздел **Artifacts** запуска со скачанным jar-файлом |
| 4 | Зелёный job `docker` (сборка и push образа) |

### ДЗ 2 (`report-hw2-docker.pdf`), раздел 8

| № | Что снять |
|---|---|
| 1 | Job `docker`: шаги `Build and push`, список тегов в логах |
| 2 | Вкладка **Packages** с образом и тегами |
| 3 | Терминал: `docker pull`, `docker run`, `curl /actuator/health`, `curl /api/info` |
| 4 | Браузер: `http://localhost:8080` — страница со списком задач |

## 5. Чек-лист перед сдачей

- [ ] Ссылка на репозиторий в отчёте совпадает с реальной.
- [ ] Оба job'а зелёные на последнем запуске.
- [ ] Артефакт скачивается и запускается (`java -jar …`).
- [ ] Образ в GHCR опубликован, пакет публичный.
- [ ] `docker run` поднимает контейнер, `/actuator/health` отдаёт `UP`.
- [ ] В PDF нет токенов и паролей.
- [ ] Титульный лист заполнен (ФИО, группа).
