# Как завершить работу и сдать отчёты

Проект, `Dockerfile`, пайплайн, README и два PDF-отчёта уже готовы.
Осталось запушить репозиторий, проверить прогон и вставить скриншоты.

Ссылка, уже проставленная в отчётах и README: <https://github.com/Lekko8/mifi_vo_HW>

## 1. Запушить репозиторий

```powershell
cd "D:\Документы\Проект по умолчанию"
git remote add origin https://github.com/Lekko8/mifi_vo_HW.git
git push -u origin main
```

Если репозиторий на GitHub был создан с README/лицензией, сначала подтяните историю:

```powershell
git pull --rebase origin main
git push -u origin main
```

Репозиторий пустой и его основная ветка — `main`, поэтому пуш запустит workflow сразу.

## 2. Проверить прогон

1. Вкладка **Actions** → запуск `CI/CD` → оба job'а зелёные.
2. Первый прогон дольше (скачивает зависимости), повторный берёт кэш.
3. Внизу страницы запуска — раздел **Artifacts** с jar-файлом.
4. Вкладка **Packages** → пакет `mifi_vo_hw` с тегами `latest`, `main`, `sha-…`.
5. Сделайте пакет публичным: **Package settings → Change visibility → Public**.
6. Скачайте и запустите образ:

```powershell
docker pull ghcr.io/lekko8/mifi_vo_hw:latest
docker run --rm -p 8080:8080 ghcr.io/lekko8/mifi_vo_hw:latest
```

Имя пакета в GHCR — это имя **репозитория** в нижнем регистре (`mifi_vo_hw`), а не `task-tracker`.
Точную команду `docker pull` показывает страница пакета.

## 3. Вставить скриншоты в PDF

Места под скриншоты обозначены пунктирными рамками с подписью «СКРИНШОТ: …».
Вставить картинки можно в Word (открыть PDF → правка), LibreOffice Draw, Acrobat
или любом редакторе PDF.

### ДЗ 1 (`docs/report/report-hw1-ci-cd.pdf`), раздел 7 — 3 скриншота

| № | Что снять |
|---|---|
| 1 | Список запусков workflow во вкладке Actions (push и pull request) |
| 2 | Логи job `build-and-test`: `Cache restored from key: …` и `Tests run: 13` |
| 3 | Раздел **Artifacts** со скачанным jar-файлом |

### ДЗ 2 (`docs/report/report-hw2-docker.pdf`), раздел 8 — 4 скриншота

| № | Что снять |
|---|---|
| 1 | Job `docker`: шаги `Build and push`, список тегов в логах |
| 2 | Вкладка **Packages** с образом и тегами |
| 3 | Терминал: `docker pull`, `docker run`, `curl /actuator/health`, `curl /api/info` |
| 4 | Браузер: `http://localhost:8080` — страница со списком задач |

## 4. Перегенерировать PDF (если понадобится)

```powershell
python docs\report\build_reports.py
```

Ссылка на репозиторий, дата и прочие данные заданы в начале `build_reports.py`
(константа `REPO_URL`, `REPORT_DATE`). ФИО в отчётах нет — требование его не содержит,
поэтому титульный лист ограничен проектом, репозиторием и датой.

Нужен Python 3 с библиотекой `reportlab` (`python -m pip install reportlab`) и шрифты
Windows (Arial, Consolas) — на этой машине всё уже установлено.

## 5. Чек-лист перед сдачей

- [ ] Оба job'а зелёные на последнем запуске.
- [ ] Артефакт скачивается и запускается (`java -jar …`).
- [ ] Образ в GHCR опубликован, пакет публичный.
- [ ] `docker run` поднимает контейнер, `/actuator/health` отдаёт `UP`.
- [ ] Скриншоты вставлены, в PDF нет токенов и паролей.
